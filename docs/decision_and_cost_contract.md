# Контракт принятия решения, матрица стоимости и открытые решения пилота

**Статус:** проектное предложение для согласования владельцем продукта и данных банка (Этап 0 ТЗ).

## 1. Единица наблюдения и семантика действий

Одна запись запроса (`POST /score`) соответствует **одной попытке инициирования банковского перевода до окончательной проводки**.

| Действие | Технический смысл для платёжного шлюза | Операционный эффект |
|---|---|---|
| `ALLOW` | Разрешить проведение перевода без трения | Нулевая задержка клиента; риск FN при пропуске мошенничества |
| `OTP` | Запросить дополнительное подтверждение клиента (SMS / Push / биометрия) | Низкая стоимость трения; отсекает автоматизированные и часть ATO-атак |
| `REVIEW` | Приостановить проводку и направить кейс в очередь антифрод-аналитика | Ограничено суточной ёмкостью команды (`max_daily_reviews`, `max_review_rate`) |
| `BLOCK` | Отклонить перевод до списания средств | Предотвращает прямой ущерб; ложная блокировка несёт риск оттока клиента |

В режиме **теневого пилота (`shadow_mode: true`)** сервис вычисляет и записывает в аудит рекомендуемое действие `action` (`ALLOW/OTP/REVIEW/BLOCK`), но возвращает платёжному каналу `effective_action = "ALLOW"` (`decision_mode = "SHADOW"`), не влияя на реальную проводку.

## 2. Предлагаемая матрица бизнес-стоимости и ограничений capacity

> [!IMPORTANT]
> Значения ниже являются **проектными предложениями прототипа** (`config/config.yaml`), а не утверждёнными тарифами банка. Пороги классификации подбираются на `validation` отдельно для каждого источника данных и никогда не переносятся из симулятора на реальный поток.

| Параметр (`config/config.yaml`) | Предложение пилота | Требует подписи владельца |
|---|---:|---|
| `agent.costs.otp_cost` | `2.0` у.е. | Владелец канала ДБО / коммуникаций |
| `agent.costs.review_cost` | `25.0` у.е. | Руководитель антифрод-мониторинга |
| `agent.costs.false_block_cost` | `150.0` у.е. | Владелец розничного продукта |
| Потеря при пропуске фрода (`FN`) | `100%` суммы перевода `amount` | Департамент управления рисками |
| `agent.capacity.max_review_rate` | `≤ 3.0%` потока | Руководитель смены аналитиков |
| `agent.capacity.max_daily_reviews` | `≤ 150` кейсов/сутки | Руководитель смены аналитиков |
| `monitoring.latency_sla_p95_ms` | `≤ 150` мс (бюджет таймаута `500` мс) | Архитектор платёжного шлюза |
| `monitoring.label_maturity_hours` | `72` ч (предварительно; для chargeback до 30–45 сут.) | Владелец претензионной работы |

## 3. Политика Fail-Safe при сбое или деградации

При недоступности ML-модели, ошибке чтения состояния признаков или превышении `scoring_timeout_budget_ms` сервис **не изобретает поведение молча**:
- Выполняется детерминированная политика `scoring.fallback_policy` (`rules_only` по умолчанию либо `hold_for_review`).
- В ответе возвращается `technical_status = "DEGRADED_FALLBACK"` и заполняется `fallback_reason`.
- Срабатывание фиксируется в БД аудита и поднимает алерт `FAILSAFE_FALLBACK_INVOKED` в `/metrics/summary`.

## 4. Чек-лист открытых решений перед интеграционным пилотом (Раздел 10 ТЗ)

- [ ] Подтвердить валюту и масштаб поля `amount` в целевом канале банка.
- [ ] Подтвердить синхронную доступность `oldbalanceOrg` до авторизации перевода (иначе установить `allow_sender_pre_balance: false`).
- [ ] Утвердить числовой SLA `p50/p95/p99` и поведение платёжного шлюза при HTTP-таймауте вызова `/score`.
- [ ] Утвердить денежную матрицу потерь (`FN`, `FP BLOCK`, `REVIEW`, `OTP`) и суточный лимит аналитиков.
- [ ] Зафиксировать период созревания меток (`unknown` → `fraud/not_fraud`) по регламенту претензионной службы.
- [ ] Согласовать сроки хранения, HMAC-соль псевдонимизации (`security.pseudonymize_ids`) и межсервисные ключи (`FRAUD_API_KEY`).
